# This check is deprecated!

Service bundles do not own unit types anymore. This check is not executed
anymore.

# **E404**: An RPC service may only be owned by a single unit type definition

## Description

There are multiple `unit_type` declarations that refer to the same Protobuf
message.

## Rationale (Why is this bad?)

**Undefined Behavior**: The `unit_type` declaration is used to generate code
that gives the type a globally unique name. If multiple service bundles could
claim the same `unit_type`, it wouldn’t be guaranteed that services looking up
the name they think is globally unique would find what they’re looking for
(since the other side might use the other name).

## Error Example

```textproto
sdv_service_bundle {
  name: "ServiceBundleA"
  unit_type {
    type: "TirePressureRPC"
  }
}
sdv_service_bundle {
  name: "ServiceBundleB"
  unit_type {
    type: "TirePressureRPC"
  }
}
```

## How to Fix

Remove `unit_type` declarations until only one per type remains.

```textproto
sdv_service_bundle {
  name: "ServiceBundleA"
  unit_type {
    type: "TirePressureRPC"
  }
}
sdv_service_bundle {
  name: "ServiceBundleB"
- unit_type {
-   type: "TirePressureRPC"
- }
}
```
