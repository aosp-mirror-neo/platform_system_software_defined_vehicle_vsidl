# This check is deprecated!

Service bundles do not own unit types anymore. This check is not executed
anymore.

# **E604**: Unit types owned by a service bundle must be defined by proto messages

## Description

There must be a Protobuf message with the name specified in the type field in a
unit type declaration.

## Rationale (Why is this bad?)

**Undefined behavior**: Unit types are used to create unique identifiers of
Protobuf publications or RPC services. If the Protobuf definition doesn’t exist,
the service bundle would register a type that doesn’t exist.

## Error Example

```textproto
--------- PROTO ---------
// empty
--------- VSIDL ---------
sdv_service_bundle {
  name: "TirePressureSensor"
  unit_type {
    # ERROR: There's no Protobuf message defined for this type
    type: "TirePressure"
  }
}
```

## How to Fix

**Alternative 1**: Add the missing Protobuf message.

```textproto
--------- PROTO ---------
+ message TirePressure {
+   option (.sdv.vsidl.v1.publication) = {
+     message_count: 8
+     model: SINGLE_PUB
+   };
+   uint32 pressure = 1;
+ }
--------- VSIDL ---------
sdv_service_bundle {
  name: "TirePressureSensor"
  unit_type {
    type: "TirePressure"
  }
}
```

**Alternative 2**: Remove the unit type declaration.

```textproto
--------- PROTO ---------
// empty
--------- VSIDL ---------
sdv_service_bundle {
  name: "TirePressureSensor"
- unit_type {
-   type: "TirePressure"
- }
}
```
