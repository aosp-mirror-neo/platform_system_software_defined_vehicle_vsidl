# **E313**: Protobuf messages / RPC services should have unique fully-qualified names

## Description

This error occurs when more than one proto message or service definition share
the same fully qualified name (FQN). The FQN is a combination of the package
name and the message/service name (e.g., `my.package.MyMessage`).

Each message and service must have a unique FQN within the entire VSIDL context
to avoid ambiguity and potential conflicts in code generation and service
discovery.

## Rationale (Why is this bad?)

**Ambiguity**: The messages / services can be mixed up in code generation.

## Error Example

```textproto
package: "com.sdv.google.test"
message TirePressure { ... }
-------------------------------
package: "com.sdv.google.test"
message TirePressure { ... } # "com.sdv.google.test.TirePressure" is already defined
```

## How to Fix

**Alternative 1**: Rename one of the messages

```textproto
package: "com.sdv.google.test"
message TirePressure { ... }
-------------------------------
package: "com.sdv.google.test"
- message TirePressure { ... }
+ message OtherTirePressure { ... }
```

**Alternative 2**: Rename one of the packages

```textproto
package: "com.sdv.google.test"
message TirePressure { ... }
-------------------------------
- package: "com.sdv.google.test"
+ package: "com.sdv.google.other"
message TirePressure { ... }
```
