# This check is deprecated!

Service bundles do not own unit types anymore. This check is not executed
anymore.

# **E405**: A service bundle may not own unit types from a different package

## Description

A service bundle attempts to declare ownership of a unit type that is defined in
an unrelated package. A service bundle can only own unit types that belong to
its own package or a sub-package.

## Rationale (Why is this bad?)

**Broken Ownership Model**: The fully-qualified name of a unit type is derived
from its owning service bundle's package and name. Allowing a bundle to "claim"
a type from an unrelated package breaks the namespacing and ownership model.

## Error Example

Given a Protobuf message in the `com.unrelated` package:

```proto
syntax = "proto3";
package com.unrelated;

message SomeType {
  // ...
}
```

A service bundle in a different package (`sdv.test`) cannot declare ownership of
`SomeType`.

```textproto
// file: sdv/test/service.vsidl
package: "sdv.test"

sdv_service_bundle {
  name: "MyService"
  unit_type {
    # ERROR: This service bundle is in package "sdv.test" but tries to
    # own a unit type from an unrelated package "com.unrelated".
    type: ".com.unrelated.SomeType"
  }
}
```

## How to Fix

Move the `unit_type` ownership declaration to a service bundle that resides in
the correct package (`com.unrelated`). The original service bundle in `sdv.test`
should not own the type.

```textproto
// --- file: sdv/test/service.vsidl ---
package: "sdv.test"

sdv_service_bundle {
  name: "MyService"
  // This bundle can no longer own .com.unrelated.SomeType
}

// --- file: com/unrelated/service.vsidl ---
package: "com.unrelated"

sdv_service_bundle {
  name: "CorrectOwner"
  unit_type {
    type: "SomeType"
  }
}
```
