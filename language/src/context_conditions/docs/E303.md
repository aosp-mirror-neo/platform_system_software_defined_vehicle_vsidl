# **E303**: User-defined service unit names must be unique per service bundle. Conflict in RPC names

## Description

There may not be two RPC servers using the same user-defined name in the same
service bundle.

## Rationale (Why is this bad?)

**Undefined Behavior**: RPC clients discover RPC servers using the FQIN, which
is built from the VM name, the service bundle’s fully-qualified name and the
service unit name. If multiple RPC servers have the same user-defined service
unit name, RPC clients couldn’t distinguish between them.

## Error Example

```textproto
sdv_service_bundle {
  name: "SeatHeatingController"
  server {
    service: "SetHeatingLevel"
    service_unit_name: "sh-one"
  }

  server {
    service: "SetHeatingLevel"
    # ERROR: This name is already used by the other RPC server in this service bundle
    service_unit_name: "sh-one"
  }
}
```

## How to Fix

Change at least one of the conflicting user-defined names.

```textproto
sdv_service_bundle {
  name: "SeatHeatingController"
  server {
    service: "SetHeatingLevel"
    service_unit_name: "sh-one"
  }
  server {
    service: "SetHeatingLevel"
-   service_unit_name: "sh-one"
+   service_unit_name: "sh-two"
  }
}
```
