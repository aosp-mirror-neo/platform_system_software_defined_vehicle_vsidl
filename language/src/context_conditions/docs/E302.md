# **E302**: User-defined service unit names must be unique per service bundle. Conflict in publisher names

## Description

There may not be two publishers using the same user-defined name in the same
service bundle.

## Rationale (Why is this bad?)

**Undefined Behavior**: Subscribers discover publishers using the FQIN, which is
built from the VM name, the service bundle’s fully-qualified name and the
service unit name. If multiple publishers have the same user-defined service
unit name, subscribers couldn’t distinguish between them.

## Error Example

```textproto
sdv_service_bundle {
  name: "TirePressureSensor"
  publisher {
    type: "Pressure"
    channel: "ONE"
    service_unit_name: "my-pub"
  }
  publisher {
    type: "Pressure"
    channel: "TWO"
    # Error: This name is already used by the other publisher in this service bundle
    service_unit_name: "my-pub"
  }
}
```

## How to Fix

Change at least one of the conflicting user-defined names.

```textproto
sdv_service_bundle {
  name: "TirePressureSensor"
  publisher {
    type: "Pressure"
    channel: "ONE"
    service_unit_name: "my-pub"
  }
  publisher {
    type: "Pressure"
    channel: "TWO"
-   service_unit_name: "my-pub"
+   service_unit_name: "my-pub-two"
  }
}
```
