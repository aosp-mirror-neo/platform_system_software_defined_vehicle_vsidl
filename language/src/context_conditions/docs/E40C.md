# **E40C**: SOME/IP `sdv_service_unit_parameterization` cannot be set if literal topic or channel are used.

## Description

This error occurs when a SOME/IP service mapping defines `sdv_service_unit_parameterization` in one or more instances, while also using literal `topic` or `channel` names in the corresponding `instance_impl`.

## Rationale (Why is this bad?)

**Mixed Mapping Models**: VSIDL supports two ways to map SOME/IP instances to SDV service units:
1.  **Parameterized**: Using `sdv_service_unit_parameterization` in instances and `service_unit` (referring to the parameter key) in the implementation.
2.  **Literal**: Omitting `sdv_service_unit_parameterization` and specifying `topic` or `channel` directly in the implementation.

Mixing these models within the same service mapping is not supported and leads to ambiguous configuration.

## Error Example

```vsidl
someip_mapping {
    someip_service_mapping {
        someip_service_id: 0x1234
        instance {
            instance_id: 1
            // Error: parameterization is defined
            sdv_service_unit_parameterization { key: 0 value: "my-unit" }
        }
        instance_impl {
            offered_event {
                simple_event {
                    sdv_unit_type: "MyType"
                    // Error: literal topic is used instead of service_unit parameter
                    topic: "my-topic"
                }
            }
        }
    }
}
```

## How to Fix

Either remove the `sdv_service_unit_parameterization` and use literal names, or use the `service_unit` parameter in the implementation.

**Option 1: Use Parameters (Recommended for multiple instances)**

```vsidl
someip_mapping {
    someip_service_mapping {
        someip_service_id: 0x1234
        instance {
            instance_id: 1
            sdv_service_unit_parameterization { key: 0 value: "my-unit" }
        }
        instance_impl {
            offered_event {
                simple_event {
                    sdv_unit_type: "MyType"
                    // Correct: refers to parameter key 0
                    service_unit: 0
                }
            }
        }
    }
}
```

**Option 2: Use Literal Names (Recommended for single instances)**

```vsidl
someip_mapping {
    someip_service_mapping {
        someip_service_id: 0x1234
        instance {
            instance_id: 1
            // Correct: no parameterization defined
        }
        instance_impl {
            offered_event {
                simple_event {
                    sdv_unit_type: "MyType"
                    // Correct: literal topic name
                    topic: "my-topic"
                }
            }
        }
    }
}
```
