# This check is deprecated!

Service bundles do not own unit types anymore. This check is not executed
anymore.

# **E605**: Unit types owned by a service bundle must be defined by only one proto messages

## Description

There may not be multiple Protobuf messages or RPC services belonging to the
same unit type declaration.

## Rationale (Why is this bad?)

**Undefined Behavior**: If there are multiple Protobuf messages or RPC services
implementing the same unit type, it wouldn’t be clear which one to choose. The
generated code would choose one of them randomly.

## Error Example

```textproto
--------- PROTO ---------
message TirePressure {
  option (.sdv.vsidl.v1.publication) = {
    message_count: 8
    model: SINGLE_PUB
  };
  uint32 pressure = 1;
}
message TirePressure {
  option (.sdv.vsidl.v1.publication) = {
    message_count: 8
    model: SINGLE_PUB
  };
  int32 pressure = 1;
}
--------- VSIDL ---------
sdv_service_bundle {
  name: "TirePressureSensor"
  unit_type {
    # ERROR: There are multiple Protobuf message defined for this type
    type: "TirePressure"
  }
}
```

## How to Fix

Remove or rename one of the Protobuf messages.

```textproto
--------- PROTO ---------
message TirePressure {
  option (.sdv.vsidl.v1.publication) = {
    message_count: 8
    model: SINGLE_PUB
  };
  uint32 pressure = 1;
}
- message TirePressure {
-   option (.sdv.vsidl.v1.publication) = {
-     message_count: 8
-     model: SINGLE_PUB
-   };
-   int32 pressure = 1;
- }
--------- VSIDL ---------
sdv_service_bundle {
  name: "TirePressureSensor"
  unit_type {
    type: "TirePressure"
  }
}
```
