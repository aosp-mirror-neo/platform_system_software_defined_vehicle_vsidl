# **E402**: SdvPublication annotation must not set channels enum for `MULTI_PUB` publications

## Description

The SdvPublication sets an `channels_enum` while also setting the `model` to
`MULTI_PUB`.

## Rationale (Why is this bad?)

**Undefined Behavior**: `channels_enum` suggests (unique) service-unit-based
discoverability subscriber side. This guarantee is not given for `MULTI_PUB`.
Subscribers would randomly get one of the publishers.

## Error Example

```textproto
message BatteryLevel {
  option (sdv.vsidl.v1.publication) = {
    channels_enum: "sdv.test.BatteryChannels"
+   message_count: 8
    model: SINGLE_PUB
  };
  uint32 level = 1;
}
```

## How to Fix

**Alternative 1**: Set `model` to `SINGLE_PUB`. Use this alternative if there’s
only one publisher.

```textproto
message BatteryLevel {
  option (sdv.vsidl.v1.publication) = {
    channels_enum: "sdv.test.BatteryChannels"
    message_count: 8
-   model: MULTI_PUB
+   model: SINGLE_PUB
  };
  uint32 level = 1;
}
```

**Alternative 2**: Use separate messages instead of channels. Use this
alternative if multiple publishers are required.

```textproto
message BatteryLevel {
  uint32 level = 1;
}
message BatteryLevelChannelOne {
  option (sdv.vsidl.v1.publication) = {
    message_count: 8
    model: SINGLE_PUB
  };
  BatteryLevel level = 1;
}
message BatteryLevelChannelTwo {
  option (sdv.vsidl.v1.publication) = {
    message_count: 8
    model: SINGLE_PUB
  };
  BatteryLevel level = 1;
}
```
