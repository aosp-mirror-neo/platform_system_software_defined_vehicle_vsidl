# **E306**: User-defined service unit names may only be used in publishers with one channel.

## Description

If a publisher definition contains more than one channel, it may not use a
user-defined name.

## Rationale (Why is this bad?)

**Undefined Behavior**: Subscribers discover publishers using the FQIN, which is
built from the VM name, the service bundle’s fully-qualified name and the
service unit name. If a publisher with multiple channels had a user-defined
service unit name, all of them would use the same user-defined name and
subscribers couldn’t distinguish between them.

## Error Example

```textproto
sdv_service_bundle {
  name: "TirePressureSensor"
  publisher {
    type: "Pressure"
    channel: "ONE"
    channel: "TWO"
    # ERROR: This publisher cannot have a user-defined name as it uses multiple channels
    service_unit_name: "my-pub"
  }
}
```

## How to Fix

Split the publisher definition into multiple definitions using different
user-defined names for each channel.

```textproto
sdv_service_bundle {
  name: "TirePressureSensor"
  publisher {
    type: "Pressure"
    channel: "ONE"
-   channel: "TWO"
    service_unit_name: "my-pub"
  }
+ publisher {
+   type: "Pressure"
+   channel: "TWO"
+   service_unit_name: "my-pub-two"
+ }
}
```
