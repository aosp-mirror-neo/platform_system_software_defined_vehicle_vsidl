# **E109**: `MULTI_PUB` publication is used by only one publisher

## Description

This warning notifies the user that a publication is specified as `MULTI_PUB`
but is only used by a single publisher.

## Rationale (Why is this bad?)

Specifying `MULTI_PUB` indicates that a publication is intended to be used by
multiple publishers. If only one publisher uses this publication, the
`MULTI_PUB` setting is redundant and can be misleading. The default model
(`SINGLE_PUB`) should be used instead for better clarity.

## Error Example

```textproto
-------- PROTO --------
message TirePressure {
  option (sdv.vsidl.v1.publication) = {
    message_count: 8
    model: MULTI_PUB
  };
  uint32 pressure = 1;
}
-------- VSIDL --------
sdv_service_bundle {
  name: "PublishingBundle"

  # WARNING: TirePressure is marked as MULTI_PUB but is only used by this publisher.
  publisher {
    type: "TirePressure"
  }
}
```

## How to Fix

**Alternative 1**: Change the publication model to `SINGLE_PUB`.

```textproto
-------- PROTO --------
message TirePressure {
  option (sdv.vsidl.v1.publication) = {
    message_count: 8
-   model: MULTI_PUB
+   model: SINGLE_PUB
  };
  uint32 pressure = 1;
}
```

**Alternative 2**: Add another publisher for this publication.

```textproto
-------- VSIDL --------
sdv_service_bundle {
  name: "PublishingBundle"

  publisher {
    type: "TirePressure"
  }
}

sdv_service_bundle {
  name: "AnotherPublishingBundle"

  publisher {
    type: "TirePressure"
  }
}
```
