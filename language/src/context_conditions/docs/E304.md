# **E304**: User-defined service unit names must be (globally) unique per unit type. Conflict in publisher names

## Description

There may not be two publishers using the same user-defined name for the same
publication.

## Rationale (Why is this bad?)

**Undefined Behavior**: Subscribers may discover publishers using their type. If
multiple publishers have the same user-defined service unit name, subscribers
couldn’t distinguish between them.

## Error Example

```textproto
sdv_service_bundle {
  name: "TirePressureSensor"
  publisher {
    type: "Pressure"
    service_unit_name: "my-pub"
  }
sdv_service_bundle {
  name: "OtherTirePressureSensor"
  publisher {
    type: "Pressure"
    # Error: This name is already used by the other publisher of this type
    service_unit_name: "my-pub"
  }
}
```

## How to Fix

Change at least one of the conflicting user-defined names.

~~~textproto
sdv_service_bundle {
  name: "TirePressureSensor"
  publisher {
    type: "Pressure"
    service_unit_name: "my-pub"
  }
sdv_service_bundle {
  name: "OtherTirePressureSensor"
  publisher {
    type: "Pressure"
-   service_unit_name: "my-pub"
+   service_unit_name: "my-other-pub"
  }
}```
~~~
