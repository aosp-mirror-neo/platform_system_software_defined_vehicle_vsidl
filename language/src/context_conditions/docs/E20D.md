# **E20D**: Channel names must follow snake case convention

## Description

This error occurs when a publisher or subscriber defines a channel name that
does not follow the snake case naming convention.

## Rationale (Why is this bad?)

**Consistency and Interoperability**: Enforcing a consistent naming convention
across all channel names improves readability and reduces the likelihood of
errors when integrating different services. Snake case is the standard
convention for channel names in the VSIDL ecosystem.

A valid snake case name: - Starts with a lowercase letter `[a-z]`. - Contains
only lowercase alphanumeric characters `[a-z0-9]` and underscores `_`. - Does
not contain consecutive underscores `__`. - Does not end with an underscore `_`.

## Error Example

```vsidl
publisher {
  message: "Speed"
  # ERROR: "MainChannel" is not in snake case
  channel: "MainChannel"
}
```

## How to Fix

Rename the channel to follow the snake case convention.

```vsidl
publisher {
  message: "Speed"
  channel: "main_channel"
}
```
