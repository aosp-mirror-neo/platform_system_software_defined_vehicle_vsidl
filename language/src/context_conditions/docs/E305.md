# **E305**: User-defined service unit names must be (globally) unique per unit type. Conflict in RPC names

## Description

There may not be two RPC servers using the same user-defined name for the same
RPC service.

## Rationale (Why is this bad?)

**Requirement for Discovery**: This enables our feature for uniquely identifying
this server regardless of the service bundle that starts it.

## Error Example

```textproto
sdv_service_bundle {
  name: "SeatHeatingController"
  server {
    service: "SetHeatingLevel"
    service_unit_name: "sh-one"
  }
}
sdv_service_bundle {
  name: "OtherSeatHeatingController"
  server {
    service: "SetHeatingLevel"
    # Error: This name is already used by the other RPC servers of this service
    service_unit_name: "sh-one"
  }
}
```

## How to Fix

Change at least one of the conflicting user-defined names.

```textproto
sdv_service_bundle {
  name: "SeatHeatingController"
  server {
    service: "SetHeatingLevel"
    service_unit_name: "sh-one"
  }
}
sdv_service_bundle {
  name: "OtherSeatHeatingController"
  server {
    service: "SetHeatingLevel"
-   service_unit_name: "sh-one"
+   service_unit_name: "sh-two"
  }
}
```
