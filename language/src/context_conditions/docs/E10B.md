# **E10B**: File in catalog is not referenced in any filegroup

## Description

This error occurs when a `.vsidl`, `.proto`, or `Android.bp` file exists within
the catalog directory (or a dependency directory) but is not included in the
`srcs` of any `filegroup` target in any `Android.bp` file within the catalog.
This check is enforced only when compiling the catalog using the `--genrule`
flag.

## Rationale (Why is this bad?)

This error is required when the `--genrule` flag is used because the GenRule
needs to copy all required files into its local sandbox to compile the catalog
correctly. If files are present in the directory but not listed as sources, the
GenRule won't "see" them, leading to a failed build.

## Error Example

Given the following file structure: `my_catalog/ ├── Android.bp ├── a.vsidl └──
b.proto (this file is not referenced)`

And `my_catalog/Android.bp` contains: `textproto filegroup { name: "my_sources",
srcs: [ "a.vsidl", "Android.bp", ], }` The file `b.proto` is not referenced in
any `filegroup`, so it will trigger this warning.

## How to Fix

Ensure that all `.vsidl`, `.proto`, and `Android.bp` files are included in a
`filegroup`'s `srcs` list in an `Android.bp` file.

```textproto
filegroup {
    name: "my_sources",
    srcs: [
        "a.vsidl",
        "b.proto",    // Add the missing file
        "Android.bp",
    ],
}
```
