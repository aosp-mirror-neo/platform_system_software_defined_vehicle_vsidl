# **E108**: Redundant explicit channel listing in VSIDL file

## Description

This warning notifies the user that explicitly listing all available channels
for a publisher or subscriber is redundant.

## Rationale (Why is this bad?)

When a publisher or subscriber is defined for a type that has multiple channels,
omitting the `channel` field implicitly uses all available channels. Explicitly
listing all of them is redundant and can make the VSIDL file harder to read and
maintain, especially if the list of channels for the type changes in the future.

## Error Example

Assuming the type `TirePressure` has two channels defined: `FRONT_LEFT` and
`FRONT_RIGHT`.

The following examples are considered redundant.

Explicitly specifying all channels in single declaration

```textproto
sdv_service_bundle {
  name: "PublishingBundle"

  publisher {
    type: "TirePressure"
    channel: "FRONT_LEFT"
    channel: "FRONT_RIGHT"
  }
}
```

Explicitly specifying all channels in multiple declarations

```textproto
sdv_service_bundle {
  name: "PublishingBundle"

  publisher {
    type: "TirePressure"
    channel: "FRONT_LEFT"
  }

  publisher {
    type: "TirePressure"
    channel: "FRONT_RIGHT"
  }
}
```

## How to Fix

Remove the `channel` declarations. By omitting the `channel` field, all
available channels are used by default.

```textproto
sdv_service_bundle {
  name: "PublishingBundle"

  publisher {
    type: "TirePressure"
  }
}
```
