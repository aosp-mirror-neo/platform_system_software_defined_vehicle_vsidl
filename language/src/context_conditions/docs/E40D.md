# **E40D**: SOME/IP `service_oriented_mapping` and `service_unit_mapping` cannot be set together.

## Description

This error occurs when a SOME/IP type mapping defines both `service_oriented_mapping` and `service_unit_mapping`.

## Rationale (Why is this bad?)

**Ambiguous Mapping Model**: VSIDL introduced `service_oriented_mapping` as a modern replacement for the older `service_unit_mapping`. Setting both creates an ambiguous configuration where it's unclear which mapping model should be used. Users should migrate to `service_oriented_mapping` exclusively.

## Error Example

```vsidl
someip_mapping {
    sdv_type_mapping {
        unit_type: "MyType"
        someip_service_id: 0x1234
        // Error: service_unit_mapping and service_oriented_mapping are both set
        service_unit_mapping {
            instance_id: 1
        }
        service_oriented_mapping {
            publication_mapping {
                topic: "my-topic"
            }
        }
    }
}
```

## How to Fix

Remove the deprecated `service_unit_mapping` and use `service_oriented_mapping` instead.

```vsidl
someip_mapping {
    sdv_type_mapping {
        unit_type: "MyType"
        someip_service_id: 0x1234
        service_oriented_mapping {
            publication_mapping {
                topic: "my-topic"
            }
        }
    }
}
```
