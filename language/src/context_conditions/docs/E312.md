# **E312**: RPC method names must be unique within a service

## Description

An RPC service cannot contain multiple methods with the same name.

## Rationale (Why is this bad?)

**Ambiguous Definition**: Protobuf service definitions do not support method
overloading based on input/output types. Having multiple RPC methods with the
same name within a single service creates an ambiguity. This prevents code
generators and RPC frameworks from correctly identifying and dispatching calls,
leading to compilation errors or unpredictable runtime behavior.

## Error Example

```textproto
service RpcService {
  # Duplicated method name in the same service is not allowed
  rpc rpc_method(google.protobuf.Any) returns (google.protobuf.Any) {}
  rpc rpc_method(stream google.protobuf.Any) returns (google.protobuf.Any) {}
}
```

## How to Fix

Rename the duplicate methods to ensure that all method names within the service
are unique.

```textproto
service RpcService {
  rpc rpc_method(google.protobuf.Any) returns (google.protobuf.Any) {}
-  rpc rpc_method(stream google.protobuf.Any) returns (google.protobuf.Any) {}
+  rpc rpc_stream_method(stream google.protobuf.Any) returns (google.protobuf.Any) {}
}
```
