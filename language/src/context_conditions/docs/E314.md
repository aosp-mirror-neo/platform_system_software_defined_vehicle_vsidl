# **E314**: Channel names must be globally unique across all publishers

## Description

This error occurs when multiple publishers use the same channel name but publish
different Protobuf message types.

## Rationale (Why is this bad?)

**Communication Errors**: Channel names identify unique communication paths for
a specific message type. If the same channel name is used for different types,
subscribers might receive data they cannot decode, or data might be delivered to
the wrong services, leading to undefined behavior or system crashes.

## Error Example

```vsidl
service_bundle {
  name: "ServiceOne"
  publisher {
    message: "TypeA"
    channel: "my_channel"
  }
}

service_bundle {
  name: "ServiceTwo"
  publisher {
    message: "TypeB"
    # ERROR: Channel name "my_channel" is already used for "TypeA"
    channel: "my_channel"
  }
}
```

## How to Fix

Ensure that each channel name is unique for its associated message type. If
different types are intended to be sent over different channels, use unique
names for each.

```vsidl
service_bundle {
  name: "ServiceOne"
  publisher {
    message: "TypeA"
    channel: "channel_a"
  }
}

service_bundle {
  name: "ServiceTwo"
  publisher {
    message: "TypeB"
    channel: "channel_b"
  }
}
```
