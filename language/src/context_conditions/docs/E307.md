# **E307**: Single Pub publisher channel is used by multiple publishers

## Description

A Proto message marked as `SINGLE_PUB` is published by more than one publisher.

## Rationale (Why is this bad?)

**Undefined Behavior**: Subscribers discover publishers using the FQIN, which is
built from the VM name, the service bundle’s fully-qualified name and the
service unit name. Publishing a `SINGLE_PUB` topic using multiple publishers
would make it ambiguous which publisher to subscribe to.

## Error Example

```textproto
-------- PROTO --------
message Pressure {
  option (sdv.vsidl.v1.publication) = {
    message_count: 8
    model: SINGLE_PUB
  };
  uint32 pressure = 1;
}
-------- VSIDL --------
package: "sdv.test"
sdv_service_bundle {
  name: "SinglePubMultiplePublishers"
  publisher {
    type: "Pressure"
  }
  publisher {
    # ERROR: This is already published by another publisher
    type: "Pressure"
  }
}
```

## How to Fix

**Alternative 1**: Change to `MULTI_PUB`. Use this if the publication is
intended to be published by multiple publishers.

```textproto
-------- PROTO --------
message Pressure {
  option (sdv.vsidl.v1.publication) = {
    message_count: 8
-   model: SINGLE_PUB
+   model: MULTI_PUB
  };
  uint32 pressure = 1;
}
```

**Alternative 2:** Remove duplicated publishers.

```textproto
-------- VSIDL --------
package: "sdv.test"
sdv_service_bundle {
  name: "SinglePubMultiplePublishers"
  publisher {
    type: "Pressure"
  }
- publisher {
-   type: "Pressure"
- }
}
```
