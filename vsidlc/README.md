# VSIDL Code Generator

VSIDL Code Generator, 'vsidlc', is used to generate service-bundle-specific MW
APIs. `vsidlc` recursively goes through the catalog folder and parses both
`*.proto` and `*.vsidl` files:

*   From `.proto` files it reads message names, rpc interfaces, and type
    definitions.
*   From `.vsidl` files it reads service bundle definitions.

Based on the found files, Rust middleware code is generated into the specified
`output` folder with the path `output/generated_rs`.

## Building VSIDLC

Use the following command for building `vsidlc`:

```bash
m vsidlc
```

## Usage

```bash
Usage: vsidlc [OPTIONS] --catalog-path <CATALOG_PATH> --output-path <OUTPUT_PATH>

Options:
  -c, --catalog-path <CATALOG_PATH>
      Path to catalog directory, i.e., the directory that contains
      .vsidl files

  -o, --output-path <OUTPUT_PATH>
      Path to parent directory of `generated_rs` folder in which
      generated files are placed

  -p, --purge
      Remove the `output_path/generated_rs` directory before
      generating new files

  -d, --dependency-catalog-path <DEPENDENCY_CATALOG_PATH>...
      Optional. Specifies the directories of the dependent
      protos outside of the `catalog_path`. Each directory must
      contain an `Android.bp` file with a `rust_protobuf` build
      target to generate Rust API for the dependent protos. In
      the case of multi-layered dependency graph, please pass
      in one list with all the directories in the graph

  -i, --ignore <IGNORE>
      Ignore context condition findings with the given IDs

  --single-catalog-lib
      Feature flag to use VSIDLC without support for multiple rust_protobuf
      libraries in the catalog and dependency folders.

  --rust-formatter <RUST_FORMATTER>
      Optional. Defines what tool is used to format rust code.
      By default will use rustfmt.
      - rust-fmt relies on either ANDROID_BUILD_TOP to be set or
        both RUSTFMT_PATH (executable) and RUSTFMT_TOML_PATH (format file)
      - pretty-please does not requires any additional setting to run
      - none does not requires any additional settings and will not
        apply any formatting to the output
      [default: rust-fmt] [possible values: rust-fmt, none, pretty-please]

  --target-api <TARGET_API>
      Optional. Specifies the target API level for code generation. Examples: "latest" [default: pdk29]

  --genrule
      Optional. When set no rust code will be generated by vsidlc. Instead Android.bp
      genrule will be added to generated_rs folder to generate up-to-date rust files
      during the build process.
      IMPORTANT: to execute vsidlc with --genrule the catalog needs to have a filegroup
      including all the catalog files (.proto, .vsidl, .bp).
      ```
      filegroup {
        name: "catalog_{name_of_catalog}",
        srcs: ["**/*"],
      }
      ```
      All the required dependencies catalogs are also required to have a filegroup
      including all files. It's important that catalog filegroup does not include/link
      to dependency catalogs and the other way around.

  -w, --no-warn
          Suppress all compiler warnings. Errors stay enabled

  -h, --help
      Print help
```

### Execution Example

The following commands will:

1.  Navigate to the directory of the `stable` example VSIDL project.
1.  Use `./catalog/` as the input directory for `.vsidl` and `.proto` files.
1.  If the `./generated_rs` directory exists, it will be deleted before
    generating code.
1.  Generate Rust code in the `./generated_rs` directory.

```bash
cd $ANDROID_BUILD_TOP/system/software_defined_vehicle/samples/vsidl/stable/

vsidlc -c catalog/ -p -o .
```

### Dependent Protos

If your `.vsidl` or `.proto` files reference protocol buffer types defined
outside the main catalog, you need to specify their locations using the `-d` (or
`--dependency-catalog-path`) option.

*   **Well-known types:** Protocol buffers from the
    [well-known types of the `google.protobuf` package](https://protobuf.dev/reference/protobuf/google.protobuf/)
    referenced from the catalog don't need to be declared using the `-d` option.

*   **External protos:** For proto dependencies not from the `google.protobuf`
    package, each dependency path passed in has to contain an `Android.bp` file
    with a `rust_protobuf` build target at the root level which generates Rust
    API for the dependent protos. Directories of transitively referenced protos
    also need to be passed.

**Tip:** This argument can also be used when `.vsidl` and `.proto` files need to
be placed in separate directories.

#### Execution Example

```bash
croot system/software_defined_vehicle/samples/vsidl/perf5/

vsidlc -c catalog/ -o . -d $ANDROID_BUILD_TOP/system/software_defined_vehicle/common/protos/com/sdv/google/test_messages -p
```

## Known Limitations

### `$ANDROID_BUILD_TOP` Must Be Defined

To find the path to the definition of the VSIDL syntax, VSIDLC currently
requires that `$ANDROID_BUILD_TOP` is set. This variable should contain the
fully-qualified path of the root of the Android repository. It can be
automatically set by calling `source build/envsetup.sh` from the repository
root.

### Hand-Written `Android.bp` File for the Catalog

Currently, VSIDLC requires a manually created `Android.bp` file in the VSIDL
catalog which defines all the proto files within the catalog.

Use the following target definition as a template and just make sure it includes
all `*.proto` files used:

```bash
rust_protobuf {
    name: "liboem_vehicle_messages_catalog",
    crate_name: "oem_vehicle_messages_catalog",
    source_stem: "oem_vehicle_messages_catalog_source",
    protos: [
        "**/*.proto",
    ],
    rustlibs: [
        "libvsidl_v1_proto_rs",
    ],
    proto_flags: [
        "-I external/protobuf/src",
    ],
    apex_available: [
        "//apex_available:platform",
        "//apex_available:anyapex",
    ],
    vendor_available: true,
    product_available: true,
    min_sdk_version: "35",
}
```
